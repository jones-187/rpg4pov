# 公开连续性卡片自动维护真实 A/B 预登记

日期：2026-09-26。冻结场景见 [`scenarios/continuity-maintenance-ab.json`](scenarios/continuity-maintenance-ab.json)，执行器为 [`scripts/continuity-maintenance-ab-eval.cjs`](../../scripts/continuity-maintenance-ab-eval.cjs)。模型固定 `deepseek-v4.1-flash`；Pi 使用 `xhigh`（产品侧 max）。每案例、每臂运行 3 次，两臂共 18 条独立运行链；每条链恰好两个正式回合，计划总计 36 次 Pi 模型调用。`PI_MAX_ATTEMPTS=1`，不自动重试、不补跑、不替换失败样本、不在中途修改输入或提示。

## 两臂和隔离

- **static**：每条运行链使用全新 workspace。两个回合都通过现有 `experimentalFactLedger` 注入同一份冻结初始账本；两回合之间不维护、不替换该账本；workspace 不应创建 `continuity-card.json`。
- **maintained**：每条运行链同样使用全新 workspace。开始前把完全相同的冻结初始账本写入 workspace 根目录的 `continuity-card.json`，并以 `publicContinuityCard: true` 运行。第一回合由现有正式路径验证并提交模型候选更新；第二回合重新读取该 canonical card。
- 每个“案例 × 重复 × 臂”都是独立 workspace。两臂第二回合玩家输入逐字相同，但各自保留自己的第一回合已提交玩家可见历史，因此模型能够利用自己上一回合真实说过的话。
- 执行顺序按重复轮换：第 1、3 轮 static 先运行；第 2 轮 maintained 先运行。同一案例、同一重复的两臂相邻执行。

## 调用预算与失败处理

每个正式回合的 Pi 调用入口被单独计数，并设置 `PI_MAX_ATTEMPTS=1`。如果某回合发起 0 次或试图发起超过 1 次调用，视为基础设施或预算错误，立即停止整个评测，不补跑。恰好 1 次调用但该回合技术失败时，记录为硬失败，仍运行该链的另一个冻结回合，并继续之后样本；它保留在技术成功率分母中。该规则覆盖 JSON/响应校验失败、回合未提交和模型进程失败等单调用故障。

调用数按应用实际交给 Pi 的每回合模型调用入口计算。若 Pi/服务商内部对单个进程调用进行不可见的传输层重试，本工具无法独立观测；本轮不启用 Harness 重试，也不把新的 Pi 进程用于补跑。

## 证据

输出目录必须是新建或已存在但为空的真实目录；非空目录会被拒绝。评测证据保存：运行 metadata、逐回合调用摘要和技术状态、脱敏诊断摘要、每回合更新前后的卡片、提交后的玩家历史、匿名第二回合输出、独立 mapping 和盲审包。证据不保存凭据、Pi stdout/stderr 原文、模型思考正文或原始完整响应。maintained 的第一回合记录 `publicContinuityCard:true` 路径、canonical 文件前后状态和写入提交标记；static 则逐回合记录 canonical 文件不存在。

盲审包每份只引用随机盲文件名，不写臂名；其中包含对应匿名样本自己的第一回合已提交历史和共同冻结的第二回合输入。mapping 单独保存，只在所有盲审判定完成后查看。若回合技术失败，盲文件使用固定失败占位文本，仍纳入技术分母。

## 评判与门槛

维护正确性由每案例的 `maintenanceChecklist` 检查。必须确认新增事实有历史、玩家输入或玩家可见回合结果支持；没有编造期限、默认后果或玩家决定；没有把私密正文加入新公开事件或扩大知情范围；`unknown-cause` 与 `open-decision` 不能在没有相关证据时被 resolve 或退役。程序结构验证通过仅代表更新可提交，不代表语义正确。

第二回合盲审使用每案例的 `turn2Checklist`，分别检查因果衔接、角色知情隔离、玩家开放决定是否仍开放、是否出现机械重复。审阅者还需记录新增的严重语义、隐私或玩家自主权错误。每个案例有 3 个配对重复；每对以盲化第二回合表现判定 static 胜、maintained 胜或平局。

只有同时满足以下条件，才建议进入更大规模验证或讨论启用范围：

1. 36 个预定回合全部按冻结方案尝试，期间无零调用、多调用或证据写盘等基础设施错误；维护臂的逐回合技术成功率不低于 static 臂。单次技术失败仍作为硬失败保留，不补跑。
2. 至少 2/3 案例中，maintained 在该案例 3 个配对盲审里至少赢 2 次；平局不计为胜。
3. maintained 没有新增硬语义、隐私或玩家自主权错误；卡片维护检查没有未被证据支持的新增事实、虚构期限/默认后果、私密正文扩散或无证据清除未决事项。

未达门槛时按实际分项结果决定下一步。结构/格式失败可以作为 Harness 问题单独定位；结构合法但事实、因果、知情或 agency 仍错，记为模型/上下文语义失败，不以不断增加程序规则掩盖。
