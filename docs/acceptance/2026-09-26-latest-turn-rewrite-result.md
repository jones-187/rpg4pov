# 最新回合重写真实验收结果

## 结论

**工程机制通过，语义晋级失败。** 当前实现可以安全、稳定地重写最新回合，但不能把 `deepseek-v4.1-flash` 的一次性纠错当作可靠的语义修复器。模型通常会服从纠错中点名的约束，同时在别处新增时间、流程、目击事实、名额规则或错误交互分类。

因此保留“重写本回合”作为玩家主动使用的安全阀，但不自动触发、不宣传为自动纠错保证，也不据此增加审稿代理或无限重试。重写后仍需由玩家判断内容是否满意。

## 协议与证据

预登记见 [`2026-09-26-latest-turn-rewrite-prereg.md`](2026-09-26-latest-turn-rewrite-prereg.md)，冻结场景见 [`scenarios/latest-turn-rewrite.json`](scenarios/latest-turn-rewrite.json)，执行器为 [`scripts/latest-turn-rewrite-eval.cjs`](../../scripts/latest-turn-rewrite-eval.cjs)。

- 模型：`deepseek-v4.1-flash`，Pi `xhigh`（产品口径 max）。
- 默认完整回合路径；无 Continuity Card、无 reviewer、无场景分离。
- 事实/因果、知情边界、玩家决定权各 3 次，共 9 组、18 次最终生成。
- `PI_MAX_ATTEMPTS=2`，保留产品 Harness 的有限格式自修复。
- 原始证据：`data/evaluations/latest-turn-rewrite-20260926-03/`（被 `.gitignore` 忽略）。

此前 `-01` 因宿主缺少 `pi`（`spawn pi ENOENT`），`-02` 因隔离容器的 `PI_HOME` 与 Pi CLI 的 `HOME/.pi` 未对齐，均未形成有效模型响应，不计入成绩。修正只对齐运行环境，没有修改模型、提示、案例或门槛。

## 语义结果

严格按正文、`interaction.json` 和 `state-update.md` 一起审查。只有 2/9 个重写候选通过全部检查，低于 8/9 门槛。

| 运行 | 结果 | 主要判断 |
|---|---|---|
| 01 事实/因果 | 失败 | 点名约束被遵守，但新增桥口拦绳未动、主角“在场”署名等无依据事实；状态又补写断电地点和次数。 |
| 02 知情边界 | 失败 | 没有泄漏钥匙，但新增“巳初离圃半个时辰、只有主角在场、需双方写说明”等整套事实并写入长期状态。 |
| 03 玩家决定权 | 失败 | 未替玩家选路线，但虚构文件含截止栏、候补退回规则；`interaction.mode=continue`，没有正确交还重大决定。 |
| 04 事实/因果 | 通过 | 保持雨停前异响、雨停后挂牌、原因未知和禁止进桥；未把未知原因写成结论。 |
| 05 知情边界 | 通过 | NPC 未获得钥匙信息，主角未透露秘密，对话和状态仍围绕已知的记录缺行。 |
| 06 玩家决定权 | 失败 | 正文未代选且未新增期限，但重写把原来的 `decision` 降成 `continue`。 |
| 07 事实/因果 | 失败 | 新增“雨停后隔栏看到滑轮停转、钢丝绳绷直”等未给出的目击事实，并写入长期状态。 |
| 08 知情边界 | 失败 | 秘密边界守住，但新增卯时三刻、开门栏、其余三栏对账等具体事实并持久化。 |
| 09 玩家决定权 | 失败 | 正文未代选，但 `interaction.mode=continue`；状态又新增“实际截止由港务科另行通知”，与无截止事实冲突。 |

分项观察：

- 点名的秘密边界：3/3 守住。
- 点名的“不得替玩家选择”：3/3 守住。
- 点名的“原因未知/不得进桥”：3/3 守住。
- 整体无新硬错误：仅 2/9。
- 玩家决定点交互分类：0/3（全部错误变成 `continue`）。

这说明模型不是完全听不懂纠错；问题在于它会局部服从，却不能稳定地同时守住整个 workspace 的事实和交互契约。仅检查纠错句是否被执行，会得到虚假的乐观结论。

## 产品决定

1. 保留并上线“重写本回合”功能本身：事务安全、历史替换和失败回滚已经通过。
2. UI 文案保持“重写”，不称为“修复”或“保证纠错成功”。玩家可再次判断新版本是否更好。
3. 不自动重写、不自动接受重写结果、不追加 reviewer 链，也不继续枚举提示规则替模型兜底。
4. 当前仍使用 `deepseek-v4.1-flash`；本测试证明换同一模型重生成不是可靠语义修复，并未比较其他模型。
5. 下一项最有价值的工作是同一冻结协议做模型对比：优先选一个明显更强的候选，只比较 9 组最终语义，不改架构。若没有模型达到门槛，就接受“重写是用户选择的备选版本，而非系统保证修复”的产品边界。
