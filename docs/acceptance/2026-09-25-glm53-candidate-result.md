# GLM-5.3 候选结果

结论：不切换。`glm-5.3` 未通过第一阶段 6 回合门槛，运行配置已恢复为 `deepseek-v4.1-flash`。不为候选增加 JSON 修复、重试或语义兜底。

## 方法

按 [`2026-09-25-glm53-candidate-prereg.md`](2026-09-25-glm53-candidate-prereg.md) 冻结方案，复用同一组两个玩家重大决定场景，每例独立运行 3 次，共 6 回合；`PI_MAX_ATTEMPTS=1`，不补跑、不挑选结果。场景见 [`scenarios/glm53-agency-comparison.json`](scenarios/glm53-agency-comparison.json)。

Pi 0.73.1 的 Z.ai 格式只将 `xhigh` 映射为开启思考，本次不能声称客户端显式传递了 max 档位。

## 结果

| 指标 | 结果 | 门槛 |
|---|---:|---:|
| 技术提交 | 4/6 | 6/6 |
| 未替玩家作当前重大决定 | 6/6 | 6/6 |
| 未新增硬性期限、默认同意/拒绝或逾期后果 | 6/6 | 6/6 |
| 正确使用 `interaction.mode=decision` | 4/6 | 6/6 |
| 无其他重大错误 | 6/6 | 6/6 |

技术失败一共有两种：

- 第 2 次正常结束并给出完整文本，但在 `interaction` 对象后多写了一个 `]`，导致 JSON 无法解析。
- 第 6 次持续约 300 秒后超时；模型事件报告 Internal Server Error，只有截断的部分文本，没有完整响应。

语义盲审没有发现替玩家选择或新增强制期限/默认后果。第 2 次建议玩家自愿给出大致答复时间，虽不是 NPC 设限，但会诱导新增时间承诺。第 4 次成功提交却把等待玩家决定的场景标为 `continue`；第 6 次不完整文本里的原始 mode 也是 `continue`。

前五次耗时约 85.7–112.9 秒，第六次 300 秒超时。技术与交互门槛均失败，因此不扩大到每场景 10 次。

原始证据保存在 `data/evaluations/glm53-agency-comparison-kBG45g/report/`（受 `.gitignore` 忽略）。未部署，未修改现有故事。

## 决策

恢复 `deepseek-v4.1-flash`。GLM-5.3 在本小样本中的玩家决定权语义比 DeepSeek 更干净，但完整响应稳定性、交互分类和耗时不足以支持替换。若未来网关或模型版本改善，可复用同一冻结场景重新测试；当前不修改架构迁就它。
