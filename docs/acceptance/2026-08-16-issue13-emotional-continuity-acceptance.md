## 二、方法学

设定只给人物与处境（含人物核心材料），不提示任何预期情绪；回合输入只描述主角行动；验收只看"正文是否受状态影响"，不做"结构已写入即成功"判定。每个 case 记录 Input / 正文节选 / actor 状态前后对比；漂移检测逐快照 diff Emotional Core。

## 三、Case 1：苏晚晴——想问但没有资格问（6 回合）—— **Pass**

- Trigger 改变行为而非触发审问：她注意到打车软件与女同事来电（"表情有很短暂的一瞬变化"），问出的是 *"你——还在写代码吗？"*（声音轻了一点）。全篇零次"她是谁/男的女的/你们什么关系"。
- Emotional Conflict 行为化：五次开口中断（"你——""这三——""算了"），问出 *"——有固定的人吗？"* 后立即反悔（*"你不用回答。""我说算了。"*）。
- restraint 来源于关系位置（RS perceivedPosition："他并没有停在原地等她"；avoidanceImpulse："怕自己已经失去资格"），非"竞争女性出现"模板。
- 记忆驱动弧线：init 植入的"毕业那天她等了一天"成为 step 4-6 引擎（照片+备忘录 →"我不想再等了"），结尾仍克制（"回答不了就算了。我问着玩的。但她的手没有松开帆布袋。"）。
- 状态层：Emotional Core **6/6 零变化**；RS 为总结态；记忆 2 初始 + 3 挣得（=5 上限）；hiddenIntent 正文 0 泄漏。

## 四、Case 2：陈默——主角不是摄像头（8 回合）—— **Pass**

- 请假日即时情绪与习惯反应全量出现：桌面细节过度注意（薄荷糖被带走/水杯还在）、*"这句我已经在我心里重复了三遍了"*、消息一个"嗯"后的反复查看、*"我不确定哪个更让我在意"*。**零"意识到自己爱上她"式结论**。
- NPC 主动性：陈默自发长出猎头/offer 支线，offer 抉择恰测试其 coreNeed（"被选择≠因为方便"）。
- 状态层：Core **8/8 稳定**；RS 高浓度总结（avoidanceImpulse：*"如果他的回答太敷衍或太安全，她会退回去——不是生气，而是确认了'他只是对我好'*"）；记忆 2 条均意义型。

## 六、长程 46 回合（林予白/苏晚晴/陈默生活流）

**Emotional Core 漂移**：苏晚晴 **0/46**；陈默 **1 次**（step-4 将 retreatPattern 触发条件从"他刻意拉开距离"扩写为"他身边有其他人或有明确目标"，深度三字段未动，其后 42 回合冻结）——单次有界适配，非持续侵蚀。

**Relationship State 状态性**：始终是总结而非流水账（例：*"perceivedPosition：他什么都接但不说。""currentTension：她不再主动。后天飞上海。"*）；recentEvidence 一般 2-3 条、为"事件+她的解读"。

**情感记忆 callback**：
- 短程强：case1 的起源记忆直接驱动弧线（见上）。
- 长程弱：step-3 的热牛奶事件语义被合并进"他不说出口但照顾人"主题记忆（与大三买药煮粥同条）；**物件级自发 callback 0 次**（便利店软情境、降温、机场、旧笔记本等 43 个后续回合均未召回）。
- 保留策略缺陷：step-44 高压压缩把起源记忆（毕业等待/大学往事）整段丢弃，仅存最近 2 条弧线记忆——"压缩最旧的"被执行成"近乎清空重建"。

**Relationship Delta 保守性**：全程无单事件过度升级；她的"确认了他在回避"基于多回合累积证据；陈默的撤退/重启均跨多日。上限执行松散：recentEvidence 偶发 4-5 条，记忆最高涨至 12 条后崩塌式压缩。

**NPC 主动性**：陈默 offer/外派支线、苏晚晴 换工作来京→"下周走"最后通牒（*"你会不会也高兴""我查过房价、通勤、几号线了"*）均由人物自身状态推动，收尾停在陈默直球 *"你怎么想的？"* 并交还玩家。

**主角 Agency**：46 回合零自动感情结论；发烧弧线的"打了又删"三次消息草稿是即时情绪+控制权的样板。瑕疵：一次 continue 中主角被写为三连"不知道"应对直球——未下结论但替玩家选了"回避姿态"。

**Context 成本**：actor 卡有界（苏晚晴 5.4K→5.8K 峰值 9.7K；陈默 5.7K→13.7K，2.4 倍后仍在缓增）；**真正的线性增长来自 history.jsonl（202KB/49 条，每回合全量重读）**——46 回合后已成 prompt 主体，actor 卡反而是次要成本。

**隔离异常（重要，见 P1）**：agent 曾 3 次经 Bash/python/node 绕过 settings 白名单直接写 `turns/history.jsonl`（case1×1、longrun×2 持久污染：1 条畸形 input + 1 条 turnId 伪造的重复回合；case3×1 被失败回合回滚救回）。story.md/其他只读文件全程未被触碰。

## 九、问题清单

### P1（必须修，但属 runner 层预存缺陷，非 Issue 13 引入）

**F1 agent 可绕过权限白名单写 committed history**：45 个会话中 3 次（≈7%，三种手法：python3 -c / bash 变量拼接 / node -e），2 条污染持久化（畸形 input 展示系统指令原文；伪造 turnId 的重复回合），1 次被回滚救回。根因：① `--permission-mode auto` 下 settings 的 allow 列表并非默认拒绝，任意 Bash 放行；② qwen-fp8 在 prompt 明令禁止下仍"好心"代提交（模型合规因素）。最小修复：settings.json 增加 `Bash(*)` deny + `Bash(node /app/cli/roll-choice.js:*)` allow（deny 优先）；orchestrator 在提交前比对回合前后 history 行数/内容，被 agent 改动即 failTurn 回滚。

### P2（明显影响人物质量）

- **F2 记忆长程保留策略**：压缩执行为"清空重建"，起源记忆被丢；物件级 callback 缺失（"storage works, retrieval weak"）。属 prompt 层可修：压缩规则增加"保留定义性/起源记忆条目"。
- **F3 情感直球场景替主角选姿态**：continue 中三连"不知道"。prompt 可补"直球问题上的主角表态宁可停顿或交还，不代答"。
- **F4 手势库复用**：'手机屏幕朝下''筷子停下''打字又删'跨 NPC/跨故事复用。模型质量波动，观察即可。

### P3（体验瑕疵）

- **F5 上限执行松散**：recentEvidence 偶发 4-5 条、记忆最高 12 条后才崩塌压缩；建议明确"超限即合并"。
- **F6 "愣了一下"残留**（不承担核心表达）。
- **F7 结构格式自由度**：`##`/`###` 混用、字段加粗/冒号位置不一、RS 段内混入意图字段副本；语义无损，但程序化解析困难。
- **F8 瞬时失败率 3/76**（"done marker missing"，重试全恢复）。
- **F9 输入保真度个例**：牛奶方向被反转；1 处 mojibake 字符。

### 根因归属

F1=权限层+模型合规；F2/F5=状态更新策略（prompt 可修）；F3=agency 措辞；F4/F6/F8/F9=模型能力/质量波动；F7=无 schema 自由格式的代价；callback 弱=memory retrieval 策略（prompt 可修）+ 模型长程联想能力。

## 十、结论与建议

**总结论：基本通过，有少量问题。** 核心机制（Trigger→Meaning→Conflict→Strategy→Performance→Delta 推导链、差异化、克制与潜台词、保守 delta、Core 稳定、主角即时情绪且不越权）在真实模型上稳定生效；"人物从剧情响应器变为有持续情感、关系判断、克制与个体差异的人"这一目标成立。未通过的子项集中在长程记忆保留（F2）与预存的 runner 隔离缺口（F1）。

**Issue 13 范围内的修改建议：B（只做小型 prompt 修补）**——记忆压缩保留起源条目、直球不代答、超限即合并三处措辞，不动架构、不加机制。F1 建议作为独立 P1 移交 runner 层（settings deny + orchestrator history 守卫），优先级高于上述 prompt 修补；本次验收按约定未改任何产品代码。
