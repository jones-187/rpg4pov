# JSON 请求约束对照：交付改善，语义质量仍未过门

沿用用户已授权的本地 qwen-fp8、隔离虚构故事与原输出额度 16,384；没有部署、修改已有故事或开启 30 回合长局。两组均复用此前成功的测试开场，不是重新初始化验收。

## 变更与离线证据

新增受控 `pi-extensions/json-response.ts`，仅通过 `before_provider_request` 将 `response_format` 设为 `{type:"json_object"}`。无工具生成阶段显式加载它，仍关闭扩展自动发现和所有模型文件工具，初始化路径不加载此扩展。路径可由 `PI_RESPONSE_EXTENSION_PATH` 设置，不可读则拒绝启动。

`tests/fixtures/pi-json-request-probe.cjs` 在既有镜像内、`--network none`、虚构密钥和本地 mock 服务下加载真实扩展。实抓请求包含 JSON 约束且没有 tools 字段，进程退出码 0。服务端响应仍须经本地结构、路径、精确替换、随机确认及回滚校验；JSON模式不等于完整schema或语义正确。

## 质量问题（不能用“提交成功”掩盖）

- 关闭推理，第1回合：玩家要求进馆并按年份摊册；最终正文停在入门，状态却记录已摊开整理。缺少有效变化，decision结尾也没有实际决策问题。
- 关闭推理，第2回合：中文正文混入 downstairs、Pocket；同一回答先称“三天前”又称“前天夜里”，未解释差异。
- 开启推理，第2回合：正文仅问最近一次潮汐钟停摆时间，没有说出第一轮发现的航海记录矛盾；world增量却称记录员“已把这层矛盾，桩桩递到了阿澜嘴上”。这会使后续状态误以为已向NPC披露证据，属于信息传递记账不准确。

因此目前只通过小样本的技术交付门槛，没有通过叙事—状态一致性质量门。不开长局，不推广实验分离链路，不部署。质量优先的未部署候选保留推理能力并加入JSON请求约束；下一步应针对“做了什么、说了什么、谁知道什么”的状态记账取证与回归，而不是继续放宽解析或单纯追求更快。
