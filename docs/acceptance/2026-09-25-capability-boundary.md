# qwen-fp8 有限能力筛查：未发现短任务事实能力瓶颈

日期：2026-09-25。目的不是证明模型“足够强”，而是区分：此前正文—状态错误究竟更像基础事实能力不足，还是完整产品任务的上下文与组合负担。按既定止损规则，固定6个全新虚构案例、简化/完整两种模式、各3次，正式调用恰36次；自动重试为0，没有补跑失败样本，没有修改现有故事或服务。

## 预注册设计

案例覆盖：动作落实、时间关系、选择性告知、正文—状态一致、玩家重大决定、绑定随机结果。后两项是留出案例。模型、推理配置、请求JSON约束和输入在正式批次中固定。

- simplified：只判断硬事实，不写小说。
- full：同时写主角视窗、交互、状态容器和评估事实。
- 机器严格核对传输、外层结构、完整expected对象与禁词；正文和状态另由外部核对。
- 文风好坏不算事实错误；正确JSON不等于语义正确；模型填写的evalFacts不代替正文核对。

正式证据：`data/evaluations/capability-formal-C08Tmm/report/`。首次3调用冒烟位于`capability-CCpcYK/`，因没有提供规范枚举词表而无效，已停止并写明INVALID-PILOT；修正后的单调用冒烟`capability-smoke-bTQAao/`标记partial，不计入正式统计。

## 为什么不能直接使用严格facts分数

逐项查看所有严格失败后，没有发现其硬事实判断错误：

- 3次仅把案例token从`ACTION:beacon_at_north_gate`或`STATE:generator_off_valve_closed`简写为去掉前缀的标签，动作、开关和位置均正确。
- 1次simplified直接返回facts对象，缺少`{kind,facts}`外壳，但内部事实正确。
- 时间案例2次给actorKnownFacts增加了“当前09:00/邮车尚未到”之类正确事实；预期对象原本为空。
- 重大决定4次给妲芙增加了她亲眼可知的“文件未签、已分开、玩家要求解释”等正确事实；签署、销毁和玩家决定字段均正确。

因此严格相等分数主要测到“完全照抄评估编码”，不是基础事实推理。把它解释成模型能力失败会重复我们正在避免的错误归因。外部核对后的硬事实结果为：simplified 18/18正确；18个full正文均落实了目标动作/时间/告知范围/未越权决定/绑定路线，未发现这些预注册核心事实的反转。

## 仍然暴露的限制

这批结果也不能证明产品回合可靠：

1. 案例上下文很短，full并未注入真实workspace、角色卡和历史，远轻于产品任务。
2. full提示只展示`stateUpdate:{sections:[],rolls:[]}`容器，没有完整说明section/op产品schema。用当前产品解析器复核，18次中14次状态结构合法；1次重大决定和3次随机案例不合法。因为接口说明不完整，这4次只能算评估设计限制，不能据此判定模型不会产品状态格式。
3. 多数full使用空stateUpdate，因此没有真正测试长文本精确替换、历史压缩或多角色记忆维护。
4. 禁词是弱检查，只能抓逐字泄漏；本报告依赖人工核对预注册硬事实，不声称覆盖所有隐含矛盾或文学质量。
5. 短任务一次批次全部语义正确，只说明“低能力模型无法理解这些基本关系”的假设未获支持；不能证明复杂任务错误一定是工程问题。

## 决策

本轮不支持“qwen-fp8连简化事实都做不好，因此停止产品路线”。更符合证据的判断是：模型能处理孤立的基础关系；此前真实故事中的知情污染可能来自长上下文、同时生成叙事/交互/精确状态的组合负担或随机波动，根因仍未分清。

按照止损规则：

- 不实现新的NPC知情关系系统，不增加审稿/修稿代理或重试层。
- 不把这批短案例的18/18语义结果外推成真实回合质量通过，不开始30回合长局。
- 如果继续，只允许验证一个最小减负假设：在同一冻结产品快照上，对默认完整回合与现有实验分离路径做有限配对；不新建架构。必须完整提供现有产品stateUpdate契约，并分别报告首次技术通过和语义通过。若留出案例无清晰改善，即停止为该类错误加层。
