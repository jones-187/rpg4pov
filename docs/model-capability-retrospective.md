# 模型能力边界复盘与工程止损规则

日期：2026-09-21。依据：本轮代码改造与真实验收记录，以及用户要求“避免无限为低能力模型兜底”。本文件约束后续工作的判断顺序，不代表新增运行时功能。

## 结论与当前决策

系统负责提供正确材料、清楚的交付接口、安全提交和可定位的失败；模型负责理解、推理和叙事。不能把模型的每次认知错误都转化为永久的工程复杂度，也不能把工程缺陷推给模型。

保留已经验证的安全底线和小型接口适配；暂停默认追加语义修复、审稿模型、多阶段生成或重试层。下一步若继续，应先做有限的能力归因评估，而不是直接实现“谁知道什么”的新系统。已有分离生成原型保持实验状态，不因已投入工作就升级为正式架构。

当前只能说：qwen-fp8 在现有任务与配置下已出现语义错误，可靠性未达到现有质量目标。**尚未证明模型能力上限，也未证明更多工程一定能解决。** 不用“模型太弱”结束调查，也不用“再加一层就好”无限继续。

截至上轮，557项本地测试和两项构建通过；它们证明程序契约，不证明故事质量。真实30回合对照未执行，没有部署。本轮复盘只改文档，不重新跑模型或修改运行逻辑。

## 二、错误归因：先区分四类

1. **工程缺陷**：正确材料没送到、配置没生效、接受残缺结果、写错文件或回滚失败。用实际调用和确定性测试证明，工程必须修，不等待模型变强。
2. **接口负担**：格式方言、多次工具配合、精确复制长文本增加了无关难度。允许一次小型、通用的简化；必须证明它减轻负担且没有放宽安全边界。
3. **任务负担或上下文组织问题**：单项任务可靠，合并后明显退化。需要简化任务与完整任务的配对证据，才能考虑拆分；“可能太复杂”不是新建多代理系统的理由。
4. **模型能力限制或随机失误**：在必要材料齐全、任务简化后，仍反复发生错误推断或事实混淆。优先记录能力限制、缩小产品承诺，而不是增加语义补丁。少量失败不能证明能力上限，少量成功也不能证明已解决。

当前“正文未披露证据，状态却记成已经告诉NPC”属于**已确认的语义错误，根因未定**。接口、任务负担和模型能力都可能参与；此前把下一步直接写成“修语义记账”跳过了这一判断。

## 三、这次应吸取的教训

- **工程修复惯性过强。** 交付失败适合做确定性修复，但跨到语义错误时，没有及时从“修bug”切换为“评估能力”。以后新增代码前先写归因与可证伪假设。
- **速度曾先于质量被优化。** 关闭推理明显缩短等待，却出现动作未落实、时间矛盾等问题。开启推理的两个样本均一次提交成功，但仍有错误，且约62/87秒；只能支持暂时质量优先的候选选择，不能证明普遍优越或长期稳定。
- **对照范围有限。** 两组从同一开场开始，但第一轮生成不同，第二轮输入上下文已经分叉；不是每轮完全同上下文的严格配对。缓存、随机性、样本少也限制因果结论。不能宣称“JSON模式根治错误”或“关推理必然劣化”。
- **重试后通过掩盖了脆弱性。** 关闭推理的两回合各需两次尝试；必须报告失败候选，不能只挑最终成功稿。
- **规则与模块叠加缺少预先停止条件。** 多个局部合理改动累计也会带来维护和诊断负担。新层必须与更简单基线比较，不能凭“理论上更严谨”保留。
- **诊断应先于重复调用。** 早期只记录“非正常结束”，不足以区分截断与服务错误；后续才补终止原因、用量、快照。今后先建立最小脱敏证据，不保存思考正文或密钥。
- **测试数量不是体验成绩。** 程序通过、安全提交、语义一致、文学表现分别报告，不能互相替代。

本地模型调用无需考虑服务费用，不意味着试验没有成本：助手额度、等待时间、代码复杂度、上下文负担和维护仍须控制。

## 四、后续试验上限与停止条件

以下是后续工作的默认约束，**不是本轮启动测试的指令**。

### 在试验开始前固定判据

写清：具体错误、最小证据、当前归因、只改变哪个变量、预期收益、总调用/尝试上限、什么结果意味着停止。没有可验证假设，不新增生产模块。

能力评估采用一个小批次：最多6个固定案例，每例在“必要材料齐全的简化任务”和“完整回合”下各跑3次，最多36次生成；关闭自动重试，记录全部成功与失败。覆盖已观察到的行动落实、时间关系、信息是否告知，而不是只重复同一个故事。固定模型、参数、输入快照；保留至少2个未用于修改提示词的案例，用于复核是否只是针对样本改好了。

这是筛查而非统计意义上的能力上限证明。事先确定每例的预期事实和允许变化；文学偏好不当作事实错误，正确JSON不当作语义正确。用人工核对或独立复核，不把同一模型的自评当权威。

### 用结果决定是否值得继续

- 简化任务仍在多个案例重复犯同类关键错误：先标记当前模型/配置不可靠，停止针对该类问题增加架构。除非有新证据，不用换个措辞开启下一轮补丁。
- 简化任务稳定、完整回合明显退化：可提出**一个最小拆分或减负方案**，但先给配对证据，不直接推广现有分离原型。
- 同一类错误最多尝试2个有明确预测的工程假设；没有在未用于调参的案例上观察到改善，或改善靠增加重试、明显增加延迟、牺牲其他质量换来，就停止加层并报告取舍。不得把同一问题改名重置上限。
- 一次通过不清零历史失败；默认不提高重试上限，不扩大输出额度来掩盖无穷推理，不增加“审稿→修稿→再审稿”的无限循环。
- 评价门槛不能在看到结果后临时改成“这次算过”。关键状态污染仍挡住质量验收，但**不过门也不意味着必须无限修到过门**：可以明确当前目标超出已验证能力，暂停该目标。

重开调查需要新的可区分证据，例如输入遗漏被证实、模型/服务有实质变化，或受控对照显示收益。仅仅“还有一次也许能成功”不是重开理由。切换模型、降低核心产品目标、部署或采用新的持久化架构，另行向用户说明并取得方向，不因止损而擅自执行。

## 五、哪些底线不能为了跑通而让步

保留失败回滚、受保护路径、完整响应校验、精确且唯一的状态替换、随机结果绑定。禁止把残缺JSON修猜成成功、用旧产物补齐、跳过失败状态只提交正文、模糊匹配后宣称精确更新成功。

这些防止程序接受已知坏结果；它们不能识别所有模型语义错误。不要对用户承诺“有校验所以不会胡编”。对无法可靠检查的内容，明确限制，而不是制造已经保证正确的错觉。

允许接受经用户认可的非关键文风瑕疵；不能偷偷接受会改变剧情事实、玩家重大决定或角色知情来源的错误。可选方向是降低场景复杂度、缩小功能承诺、保留人工纠错，或在用户允许时比较其他模型；本轮不实施这些变更。

## 六、下一次开始工作时

先读本复盘，不从历史报告中“下一步修语义记账”直接开工。当前推荐顺序：**有限能力归因 → 决定修、减负还是停止 → 有收益证据才改代码**。不新增语义修复层，不自动开展长局，不重新调查已经确认的参数事实。

证据来源：[首轮真实验收](acceptance/2026-09-20-real-pilot.md)、[完整响应复测](acceptance/2026-09-20-complete-response.md)、[推理控制核验](acceptance/2026-09-20-thinking-control.md)、[JSON与推理对照](acceptance/2026-09-21-json-response.md)。这些是历史记录，保留当时判断；本文件更新后续决策规则，不抹去原始失败。

## 七、首次有限筛查结果（2026-09-25）

已按上限完成6案例×2模式×3次、无重试的36次正式调用。短上下文的预注册硬事实经外部核对全部正确，包含两个留出案例；严格机器分数的失败主要来自评估标签、外层包装和额外但正确的actorKnownFacts，不能当成能力失败。full的产品状态schema有4/18不合法，但评估提示没有完整提供该schema，不能据此归因模型。

因此“模型连孤立基础关系都不可靠”的假设暂未得到支持；真实产品语义错误仍可能来自长上下文和组合负担。下一步仍受本文件止损约束：只允许一个冻结快照上的最小减负配对，不新增语义系统；没有留出收益就停止。完整证据和限制见[有限能力筛查报告](acceptance/2026-09-25-capability-boundary.md)。

## 八、唯一减负对照的结果（2026-09-25）

已按上述许可启动默认完整回合与现有场景分离原型的冻结快照对照。分离路径第一次规划即耗尽16,384输出token，产生损坏JSON和长重复文本，未进入渲染阶段；因此预注册“分离路径技术成功6/6”门槛已不可能满足，实验在3次已完成调用后提前停止。默认路径两个回合均技术提交成功：未披露证据边界通过；重大决定没有被代选，状态也保留待定，但交互错误标成`continue`。

据此，分离原型没有证明减负收益，反而把规划任务变成更重的结构化合同。它保持默认关闭，不通过提高输出上限、增加重试、修猜残缺JSON或新增审稿层挽救。当前证据也不支持“模型整体无能力”：默认路径能完成核心事实推理；更准确的限制是模型在复合 schema 与交互分类上可靠性不够稳定。完整结果见[最小减负对照报告](acceptance/2026-09-25-de-load-boundary.md)。至此本轮能力归因路线停止；没有新证据不重开。

## 九、事实注入 A/B 与当前暂停结论（2026-09-25）

后续真实 A/B 给出了新的可区分证据。通用薄事实账本会同时放大正确时间线与不该进入表演层的秘密信息：第二轮时间因果胜2/3，但开放决策胜0/3，并新增一次NPC疑似越权知情。问题不是“事实越多越好”，而是模型会优先使用被显式强调的信息，无法稳定地自行区分“模型可见”与“角色可见”。

窄化后的 Public Continuity Card 不再重复private正文，只提供抽象知情边界，并把未明确的截止、稀缺性、默认后果和不可逆影响保持为未知。第三轮18次单调用、零重试 A/B 中，卡片在时间因果胜2/3、开放决策胜3/3，两个有效隐私输出无新增泄露；8个有效pair合计胜6个。唯一卡片技术失败是非法JSON，Harness已拒绝提交。它支持“上下文组织能改善语义”，不支持“当前模型已全面可靠”，也不支持用格式失败否定已经观察到的语义收益。

因此当前停止点是：保留默认关闭的公开连续性卡片，不恢复秘密正文注入，不立即换模型，不继续枚举提示规则。下次只研究卡片候选的来源与生命周期，并继续把格式、语义、文学质量分开计分。自动提取和跨回合维护尚无证据，不能因单回合冻结卡片有效就宣布生产架构完成。完整证据见[通用账本第二轮](acceptance/2026-09-25-fact-ledger-ab-round2-result.md)与[公开连续性卡片第三轮](acceptance/2026-09-25-public-continuity-card-ab-result.md)。
